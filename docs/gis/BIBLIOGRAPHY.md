## F. 学术论文

(引用自 01_DESIGN_GOALS.md)


发现 1：原子操作（create/split/merge）并非成熟范式
  搜索了"LLM 原子空间操作 GIS 编辑"的论文——零命中。所有论文都是关于空间查
  询（NL2SQL），而非空间编辑。没有任何已发表系统描述过 LLM 输出离散的
  create/split/merge 操作对 GIS 图层执行。这意味着我们的原子操作设计是新颖  的，而非标准范式——风险更高，但差异化也更大。

  发现 2：主导范式是"Plan-then-Execute"（意图 -> 优化）

  ┌───────────┬────────┬─────────────────────────────┬───────────────┐
  │   系统    │  会议  │            范式             │ 与我们项目的  │
  │           │        │                             │    相似度     │
  ├───────────┼────────┼─────────────────────────────┼───────────────┤
  │           │ SIGSPA │ 文本 -> LLM 分区命令 ->     │               │
  │ UrbanXpla │ TIAL   │ 结构化建筑规格 -> 3D        │ 高——直接对应  │
  │ in        │ 2025   │ 渲染。可解释推理和可追溯性  │ 村庄规划      │
  │           │        │ 是核心功能。                │               │
  ├───────────┼────────┼─────────────────────────────┼───────────────┤
  │           │        │ Plan-then-Execute：LLM      │ 高——与我们的  │
  │ Text-to-3 │ 2026   │ 规划器将文本转换为结构化城  │ PARSE + MIP   │
  │ D City    │        │ 市计划 -> PCG 执行器执行。  │ allocate      │
  │           │        │                             │ 模式完全相同  │
  ├───────────┼────────┼─────────────────────────────┼───────────────┤
  │           │ AAAI   │ LLM 提取约束 -> 整数规划优  │ 中——将 LLM    │
  │ Co-Layout │ 2026   │ 化。从粗到细的策略。        │ 约束提取与 IP │
  │           │        │                             │  求解器配对   │
  ├───────────┼────────┼─────────────────────────────┼───────────────┤
  │ Intelli-P │ WWW    │ LLM + DRL：LLM              │ 中——使用 DRL  │
  │ lanner    │ 2026   │ 制定目标，强化学习优化，多  │ 而非 MIP      │
  │           │        │ 利益相关方评分。            │               │
  ├───────────┼────────┼─────────────────────────────┼───────────────┤
  │ Prompt-to │        │ 多代理：NLP -> 规划 -> 布局 │ 中——验证反馈  │
  │ -Plan     │ 2026   │  -> 验证 ->                 │ 循环模式      │
  │           │        │ 渲染。带反馈的验证循环。    │               │
  └───────────┴────────┴─────────────────────────────┴───────────────┘

  清晰结论：整个领域都采纳了"意图 -> 优化"管道。我们的 PARSE（意图提取）+
  MIP allocate（优化）+ generate（程序化合成）设计完全符合 2025-2026 年的
  SO
