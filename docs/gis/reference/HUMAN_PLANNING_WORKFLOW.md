## 1. 权威工作流程（广东省技术指南 §二）

村庄规划编制四阶段（前两阶段是系统的核心覆盖范围）：

| 阶段 | 人类规划师工作 | 系统对应 | 覆盖 |
|------|---------------|---------|------|
| **现状调查** | 资料收集 + 外业调查，形成规划工作底图 | ANALYZE 摄入 | ✅ 矢量/⚠️ 栅格 |
| **规划编制** | 科学规划 + 合理布局 + 村民协商，形成规划成果 | PLAN 闭环 | ❌ 单向 |
| **规划报批** | 乡镇政府编制，报上级审批，村内公示 30 日，村民会议同意 | 行政流程 | ❌ 不覆盖 |
| **规划公告** | 村委会保存 + 公告，作为村规民约执行 | 行政流程 | ❌ 不覆盖 |

### 1.1 现状调查的工作底图要求

- **坐标系**：2000 国家大地坐标系（CGCS2000）
- **比例尺**：一般 1:2000，可 1:1000 或 1:500
- **底图数据**：第三次全国国土调查数据成果（或最新土地变更调查）+ 数字线划图（DLG）+
  比例尺不低于 1:2000 的地形图或国土数字正射影像图（DOM）
- **补充数据**：农村地籍调查数据、地理国情普查及监测数据

> **系统启示**：工作底图 = 矢量（三调/地籍）+ 栅格（DOM/DEM/DLG）。系统当前只摄入矢量，
> 栅格（DEM/DOM）全部 🔴 缺失。栅格是地形分析、双评价、建设适宜性的输入，不可跳过。

### 1.2 规划编制的协同性

规划编制不是规划师独断，需"组织村民充分发表意见，协商确定规划主要内容"。这对应系统的
**人机协同底线**（`01_DESIGN_GOALS §9`）：不确定性由人消除，Agent 不做规划决策。

## 2. 规划内容（七大方面）

广东省技术指南 §三规定规划内容七方面，是系统 PLAN 阶段必须覆盖的维度：

| # | 规划内容 | 核心要求 | 系统对应 |
|---|---------|---------|---------|
| 1 | 村庄发展目标 | 落实耕地保有量/基本农田/建设用地规模等约束性指标 | 指标表（附表 1） |
| 2 | 生态保护修复 | 落实生态红线，明确生态空间管制规则，提出修复整治措施 | 生态红线层 + 管制规则 |
| 3 | 耕地和永久基本农田保护 | 落实永久基本农田，农田整治/垦造水田/拆旧复垦安排 | 农田保护层 + 管制规则 |
| 4 | 历史文化传承与保护 | 划定历史文化保护线，风貌控制要求，古驿道策略 | 历史保护层 + 管制规则 |
| 5 | 产业和建设空间安排 | 产业发展空间/农村住房/基础设施和公服设施；可"留白"≤20% 有条件建设区 | 用地布局 + 项目表 |
| 6 | 村庄安全和防灾减灾 | 避开灾害区，消防通道，应急庇护场所 | 灾害点 + 安全控制线 |
| 7 | 近期建设行动 | 明确近期项目资金规模/筹措/责任主体/建设方式 | 近期建设项目表 |

> **系统启示**：当前 `analyze_dimension` 的维度划分应与这七方面对齐。管制规则（附录 3）
> 的 6 大类直接对应前 6 方面，是 PLAN 阶段的核心文本产出，不应降级为 P2。

## 3. 规划成果："一图一表一规则" + 可选丰富成果

广东省技术指南 §四规定**基本成果**为"一图一表一规则"，有条件的地区可丰富成果。

### 3.1 一图：村庄规划总图（附录 1）

- **比例尺**：不低于 1:2000
- **底图**：国土数字正射影像图或地形图
- **五条核心控制线**：生态保护红线、永久基本农田保护红线、永久基本农田储备区、
  乡村历史文化保护线、宅基地建设范围线
- **留白管控区**：有条件建设区（≤现状建设用地 20%，不占基本农田和生态红线）
- **用地布局**：按附录 5 用地分类表分色填充（生态/农业/村庄建设/交通水利及城镇用地）
- **附图表**：附表 1（规划目标表）+ 附表 2（土地利用结构调整表）直接附在图幅上
- **图框要素**：指北针、比例尺（线段+数字）、CGCS2000 公里网格线、图例、图名、制图单位/日期

### 3.2 一表：近期建设项目表（附录 2）

11 列结构，8 大类项目：

| 列 | 字段 |
|----|------|
| 1-2 | 序号、项目类型 |
| 3 | 项目名称 |
| 4 | 空间位置 |
| 5-6 | 用地面积、建筑面积 |
| 7-8 | 资金规模、筹措方式 |
| 9-10 | 责任主体、协作部门 |
| 11 | 建设方式、备注 |

8 大类项目：生态修复整治 / 农田整治 / 垦造水田 / 拆旧复垦 / 历史文化保护 / 产业发展 /
基础设施和公共服务设施建设 / 人居环境整治。

### 3.3 一规则：村庄规划管制规则（附录 3）

6 大类，以村规民约方式表述，"文字易懂、内容好记、管理可行"：

1. **生态保护**：红线范围 + 禁止建设活动 + 生态用地名录
2. **耕地和永久基本农田保护**：基本农田面积 + 集中分布区 + 占用审批程序 + 设施农用地管理
3. **历史文化传承与保护**：文保单位名录 + 历史文化保护线 + 修缮审批
4. **建设空间管制**：
   - 产业发展空间：经营性建设用地建筑密度/高度/容积率/绿地率
   - 农村住房：宅基地面积上限/建筑层数/高度/风貌
   - 基础设施和公服设施：退线距离/设施用地保护
5. **村庄安全和防灾减灾**：避开灾害区/消防通道/应急庇护场所
6. **其他管制规则**：各村实际情况制定

> **系统启示**：管制规则是"一规则"的全部内容，占基本成果的三分之一。当前系统把它降级
> 为"P2 后续处理"是重大偏差。每条规则都含量化限值（密度/高度/容积率/退线），对应
> `SpatialConstraint` 的 building_constraint 扩展，且需溯源到上位依据。

### 3.4 可选丰富成果

- **规划文本**：含村庄发展目标、生态保护修复、耕地和永久基本农田保护、建设用地布局、
  历史文化传承与保护、村庄安全和防灾减灾、近期建设行动七项内容
- **规划图件**：村庄用地现状图、村庄建设项目布局规划图等
- **村庄规划数据库**：符合附录 4 要求

可选项：规划文本.pdf 及其他规划图件.jpg。

### 4.2 空间数据库规范

- **格式**：Personal Geodatabase（.mdb），ArcGIS 9.3 以上

- **容差/分辨率**：Tolerance 0.001，Resolution 0.0001
- **4 必选图层**：GHCFW（规划村范围）、QMDLTB（期末地类图斑）、TDYT（土地用途分区）、
  JSYDGZQ（建设用地管制区）

### 4.3 数据质量 8 条硬约束

| # | 约束 | 系统对应 |
|---|------|---------|
| 1 | 不得调整永久基本农田 | MIP 硬约束锁定 |
| 2 | 不得调整禁止建设区范围 | MIP 硬约束锁定 |
| 3 | 建设用地规模不得增加 | 指标校验 |
| 4 | 建设用地规划为非建设用地规模不能增加 | 指标校验 |
| 5 | 永久基本农田图斑范围内土地规划用途必须为农用地 | conflict/detector |
| 6 | 允许建设区和有条件建设区范围内不能有永久基本农田图斑 | conflict/detector |
| 7 | 有条件建设区内不能规划有建设用地 | layout_validator |
| 8 | 限制建设区内不能有新增的规划城乡建设用地 | layout_validator |

## 5. 专业分析方法体系（教材）

规划编制前期的"现状调查分析"不是简单数据堆叠，而是一套分析方法体系。以下来自
《城市规划原理》吴志强等、《实用性村庄规划编制手册》李巍等。

### 5.1 调查方法

- **现场调查法**：实地踏勘
- **资料搜集**：上位规划、三调、地籍、地理国情
- **数据描述分析**：现状数据的统计描述

### 5.2 自然环境分析（栅格分析基础）

| 分析 | 内容 | 系统工具（待建） |
|------|------|-----------------|
| 地形条件分析 | 高程/坡度/坡向/起伏度 | `gis_analyze/terrain.py` |
| 城市用地适用性评价 | 自然条件综合适宜性分级 | `gis_analyze/suitability.py` |
| 环境容量分析 | 水/大气/噪声容量 | （远期） |

### 5.3 双评价（三区三线划定依据）

- **生态保护重要性评价**：生态系统服务功能重要性 + 生态敏感性
- **农业生产适宜性评价**：土地资源 + 水资源 + 气候 + 环境 + 灾害
- **城镇建设适宜性评价**：高程 + 坡度 + 坡向 + 地质灾害 + 交通可达性 + 基本农田

双评价成果空间落位 -> 三区三线衔接。这是人类规划师划定生态/农业/建设空间的科学依据，
系统不能跳过双评价直接生成分区。

### 5.4 生态分析方法

- **生态适宜性分析法**：评价指标与因子分级 -> 居住生态位因子分析 -> 综合分析
- **生态敏感性分析法**：敏感性程序 -> 指标体系建立 -> 因子分析 -> 综合分析

### 5.5 评价与决策方法

- 层次分析法（AHP）、交叉影响分析、情景分析法

> **系统启示**：这些分析方法对应 ANALYZE 阶段的工具集。当前系统 `tools/gis_data/analytics.py`
> 只有可达性/覆盖/等时圈，缺地形/双评价/适宜性/敏感性。规划决策必须有分析依据，否则
> 输出不可解释（违反 `00_PLANNING_SYSTEM_VISION §3.3`）。

## 5.5 空间定位与地名解析（空间锚定方法论）

> **用途**：支撑系统从自然语言地名（"刘村小组东侧、晒谷场北边"）解析到具体 GIS 图斑
> 的完整方法论。这是 `create` 操作（原子操作中的项目落地）的前置依赖。
> **外部验证**：EACL 2026 "Coordinates from Context" 论文验证了 LLM 空间推理 + 传统
> Gazetteer 混合方法的有效性。

### 5.5.1 人类规划师如何定位

村庄规划中，人类规划师通过以下方式将规划文本中的地名转化为空间位置：

1. **现场踏勘**：驻村调研，在实地标注"园寨"、"社前"等自然村的位置和范围
2. **ArcGIS/QGIS 手工标注**：在规划工作底图上，根据调研结果手工绘制规划地块，
   用 DLMC（地类名称）字段聚类查找同名地块
3. **地名 -> 图斑匹配**：通过 DLMC 字段（如"园寨"）模糊匹配当前地类图斑的名称，
   结合 DLBM 编码筛选候选地块
4. **空间关系推理**：若文本描述"晒谷场北边"，规划师在底图上找到晒谷场图斑，
   向北偏移分析其北侧相邻地块

### 5.5.2 地名分类与语义标注体系

参考 villages-ML 项目（GitHub: jengzang/villages-ML，285,000+ 广东省自然村坐标），
地名可分为 9 种语义类别：

| 类别 | 示例 | 空间定位策略 |
|------|------|-------------|
| 聚落 | 园寨、社前、田坑 | 直接匹配自然村锚点（VillageGroup） |
| 方位 | 东侧、北边、西南 | 从参照物向指定方向偏移 |
| 山地 | 分水坳、清明坳 | 匹配 DEM 地形特征（山脊/山谷） |
| 水系 | 沿河、溪边 | 匹配水系矢量图层，缓冲分析 |
| 农业 | 晒谷场、秧地 | 匹配 DLMC 字段 + 现状地类（DLBM） |
| 植被 | 林地、竹林 | 匹配 DLBM 编码（0301/0302/0307） |
| 基建 | 村口、桥头 | 匹配道路/桥梁/设施 POI |
| 姓氏 | 刘村、李屋 | 自然村名 ↔ VillageGroup 关联 |
| 象征 | 古树、庙前 | 匹配注记点（CurrentAnnotation） |

### 5.5.3 组合性位置描述解析策略

对"刘村小组东侧、晒谷场北边空地"这类复合描述，采用**分层解析**：

```
Step 1: 主锚点定位
  "刘村小组" -> Gazetteer 查询 -> VillageGroup_3 (中心坐标 116.XXX, 24.XXX)
  -> 候选地块: [parcel_082, parcel_083, ..., parcel_105] (23个)

Step 2: 副锚点定位
  "晒谷场" -> DLMC 模糊匹配 "晒谷场" -> 无直接匹配
  -> 语义展开: 晒谷场 = 农业设施 = DLBM 1510 (设施农用地)
  -> 在 VillageGroup_3 范围内筛选 DLBM=1510 的地块
  -> 找到 parcel_089 (设施农用地, 1200㎡)

Step 3: 空间关系推理
  "东侧" -> 从主锚点中心向东偏移 200m 搜索半径
  "北边" -> 从晒谷场(parcel_089)向北偏移，分析相邻地块
  -> 北侧邻接地块: parcel_088 (空闲地, 800㎡)

Step 4: 候选排序
  parcel_088: 空闲地, 800㎡, 在建设边界内, 不占基本农田 ✅
  -> 置信度: 0.85 (双锚点交叉验证)
```

### 5.5.4 混合方法设计：Gazetteer + LLM 空间推理

**外部验证**：EACL 2026 "Coordinates from Context: Using LLMs to Ground Complex
Location References"（Masis & O'Connor, UMass Amherst）发现：

- LLM 在**生成准确的地理事实性知识**（中心坐标）方面表现不佳
- 但 LLM 在**给定事实性知识的情况下进行空间推理**方面表现良好
- 经过微调的小型 LLM 可以达到与大型模型相当的性能
- 使用 bounding box 链接位置提供了简单且信息丰富的定位方式

**系统实现路径**：

```
输入: "刘村小组东侧、晒谷场北边空地"
       ↓
┌─ Gazetteer 层（确定性）──────────────────────┐
│ 1. 天地图地理编码 API: "刘村小组" -> 坐标   │
│ 2. villages-ML: 285K 广东自然村匹配          │
│ 3. 候选 VillageGroup + 范围内地块列表         │
│ 4. DLMC 字段模糊匹配: "晒谷场" -> 地块       │
│ 5. 几何计算: 邻接关系/方向偏移/缓冲区         │
└──────────────┬──────────────────────────────┘
               ↓ 候选地块列表 (JSON)
┌─ LLM 推理层（语义）──────────────────────────┐
│ 输入: 原始文本 + 候选地块JSON + 约束条件      │
│ Prompt: "基于候选地块和空间关系推理，          │
│          确定最佳操作目标地块"                │
│ 输出: 排名的候选地块 + 置信度 + 推理链        │
└──────────────┬──────────────────────────────┘
               ↓
SpatialAnchor {
  reference: "刘村小组",
  offset: "东侧",
  secondary_ref: "晒谷场",
  secondary_offset: "北边",
  candidate_parcels: ["parcel_088", "parcel_082"],
  confidence: 0.85,
  resolution_status: "anchored",
  reasoning_chain: "步骤1: Gazetteer定位刘村小组->VillageGroup_3...",
}
```

### 5.5.5 与本系统 PARSE Agent 的集成点

当前 PARSE Agent 已有 `resolve_place` 工具（Gazetteer + Haversine），但：

- **已实现**：`_auto_fill_spatial_anchor()` 将 Gazetteer 结果注入 `SpatialAnchor.candidate_parcels`
- **未实现**：LLM 空间推理层（LLM 推理候选排名 + 置信度赋值）
- **未实现**：组合性副锚点解析（"晒谷场"、"东侧" 等语义要素）
- **未实现**：GeoNames/OSM 回退（Gazetteer 未命中时）
- **Gazetteer 初始化**：需确认 `_gazetteer` 在 PARSE 调用前已初始化（天地图 API key 配置）

## 6. 规划体系上下位关系

村庄规划不是孤立的，处于国土空间规划体系的末端：

```
省级国土空间规划
  └─ 市级国土空间总体规划
      └─ 县级国土空间总体规划（如平远县）
          └─ 乡镇级国土空间总体规划（如泗水镇）
              └─ 村庄规划（"多规合一"实用性规划）
```

- **上位传导**：耕地保有量、基本农田保护面积、建设用地规模等约束性指标由上位规划下达，
  村庄规划必须落实。
- **数据衔接**：村庄规划数据库须与镇级土地利用总体规划数据库衔接。
- **"多规合一"**：村庄规划是"多规合一"的实用性规划，整合土地利用、建设、产业、生态等。

> **系统启示**：`SpatialPlanningIntent` 的指标字段需区分"上位传导"vs"本级确定"（见
> `diagnostics/04 K3`）。上位规划文档已在 RAG 库（`05_上位规划/`），可作为约束来源。
> RAG 检索应能定位到具体上位条款，支撑条款级溯源。
