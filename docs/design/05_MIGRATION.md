## Ordered implementation sequence

1. 保持 L1 输入和 live terminal-state 的 fail-closed 行为，并修复并发 L3 的终态/进度投影滞后。
2. 重构 L3 内容层级和 target admission，阻断 claim → spatial target 的机械膨胀；为每个可执行项目包产出 planning role、typed parameters、对象位置和 source lineage。
3. 完成 GROUND 的 candidate/geometry/constraint/relation/source lineage，并让 completeness 真正阻止求解和推荐。
4. 建立 `PlanningDeliberationGraph`，先交付 decision-case/framing/closed-set prototype/tool registry/evaluation，再加入 critic、information-gain stop 和 typed upstream return；ScenarioOptimizer 降为确定性工具门面。
5. 扩展 ScenarioSet 的 prototype/tool/critic lineage 与 bounded-search statement；删除 SiteSelectionDecision 和旧 projection/select service，冻结 `ApprovedOutcomeEnvelope`。
6. 建立 `ConstrainedMaterializationGraph`，把复杂执行变成 recipe planning→staging observation→diagnosis→typed recovery→equivalence validation；简单路径保留 zero-LLM fast path。
7. 强制 missing/stale approval fail-before-model/tool 和 atomic all-or-nothing commit，完成 one-worker-fails、非等价恢复与 replay 验收。
8. 完成独立 VALIDATE、RECONCILE 和 same-run DELIVER，确保规划图层只来自本次 committed state。
9. 创建全新真实会话跑完整链路，用 Playwright 检查前端状态、规划图层、证据定位、deliberation/recovery audit 和交付物；最后才根据真实截图与最近修改更新周报。
