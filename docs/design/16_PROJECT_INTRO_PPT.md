# 村庄规划智能系统项目介绍（精简 PPT 版）

> 目标设计介绍稿。适合项目立项、方案汇报和技术路线说明；不展开当前实现进度。
> 外部对比只用于提炼能力维度，不出现具体项目名称。

## 第 1 页：项目定位

### 村庄规划智能系统

面向村庄规划场景，融合自然语言理解、知识图谱、GIS 空间分析、约束求解和多模态证据，形成从
“资料输入”到“规划交付”的智能化工作流。

### 核心理念

```text
LLM 负责理解与提议
证据负责支撑与追溯
空间算法负责计算与落地
规则 / Solver / 人工负责最终把关
```

系统不是一次性生成地图，而是一条可解释、可校验、可恢复的规划生产线。

---

## 第 2 页：解决什么问题

传统规划智能化通常面临：

- 报告、GIS、知识库和图片资料相互割裂；
- LLM 能理解文字，但容易缺少本地空间事实；
- 地名、设施和自然村关系复杂，容易出现错位；
- 规划建议、空间选址和地块变化之间缺少完整链路；
- 生成结果难以解释、复核和持续修正。

### 本项目的解决思路

将规划过程拆为四条可追踪链路：

```text
资料 → 事实与证据 → 规划目标 → 空间决策 → 执行变化 → 校验交付
```

每个结论都保留来源、版本、证据和影响范围。

---

## 第 3 页：系统能做什么

### 六项核心功能

1. **多源资料理解**：读取规划报告、表格、GIS、图片、扫描图和遥感资料。
2. **规划知识组织**：通过 L1/L2/L3 形成观察事实、发展策略和规划方案。
3. **证据检索与智能调度**：按证据缺口自动选择 KG、空间数据、报告、外部搜索或专业计算工具。
4. **空间选址与方案求解**：结合约束、容量、服务范围、道路和地块条件生成候选与组合方案。
5. **确定性空间执行**：将批准的规划决定转换为项目、设施、道路、分区和地块变化。
6. **校验与成果交付**：自动检查面积、分类、几何、拓扑、网络和图面质量，生成地图、图层、报告和交付清单。

---

## 第 4 页：总体工作流程

```text
数据与资料接入
  → L1 观察：事实、问题、地点、证据
  → L2 策略：目标、缺口、约束、优先级
  → L3 方案：规划主张与干预候选
  → PlanningProgram：确定性组装规划目标
  → GROUND：证据与空间候选绑定
  → SELECT：候选分配与组合求解
  → EXECUTE：项目 / 设施 / 道路 / 分区落地
  → VALIDATE：质量检查与定向反馈
  → RECONCILE：目标、决策、执行和成果对账
  → DELIVER：地图、图层、报告和交付包
```

L1/L2/L3 是认知与规划视图；空间执行必须使用结构化、带证据的规划对象，不能直接执行模型文本。

## 第 5 页：项目核心优势

| 优势 | 体现 |
|---|---|
| **本地空间理解** | KG、自然村、设施、道路、地块和 BSM 统一关联 |
| **证据可追溯** | 每个事实、候选、决策和成果都保留来源与 provenance |
| **反向地点解析** | “祠堂@某自然村”可反查自然村位置、几何和空间标识 |
| **LLM 智能但不失控** | LLM 负责提议，策略和确定性模块负责批准与执行 |
| **复杂约束求解** | 面积、容量、服务半径、道路连通和保护约束统一进入求解 |
| **多模态融合** | 报告、图片、图例、扫描图和遥感信息进入同一证据链 |
| **失败可恢复** | 支持 Gate、HUMAN、checkpoint、分支、重放和定向重算 |
| **成果可交付** | 输出规划图、GeoJSON/图层、土地平衡、报告和交付清单 |

## 第 6 页：智能调度与证据中心

### 智能调度机制

```text
证据缺口 / 阶段状态
  → LLM DispatchProposal
  → DispatchPolicy 校验
  → DispatchCommand
  → 检索、专业 Worker 或空间 Solver
```

LLM 可以选择“下一步做什么”，但不能直接修改规划状态、生成权威坐标、跳过 Gate 或触发未经批准
的空间执行。

### EXPLORE 与 Exa

```text
本地 KG / 报告 / Bundle / 历史证据
  → ExternalSearchPort
  → Exa 等外部搜索适配器
  → 带来源的 EvidenceBundle
```

外部搜索用于补充政策、背景、公开资料和证据线索；不能直接替代本地空间数据，也不能直接产生
坐标、BSM、规划分类或选址决定。

## 第 7 页：与常见方案的能力差异

> 该页只做能力层面对比，不列举具体项目名称。

| 能力维度 | 常见智能问答 / 单点 GIS 工具 | 本项目目标 |
|---|---|---|
| 输入范围 | 文本或单类空间数据 | 报告、GIS、KG、图片、扫描图、遥感等多源资料 |
| 空间理解 | 关键词、地理编码或单次空间分析 | L1 事实 + KG 关系 + 几何 + BSM + 证据评分 |
| 任务范围 | 回答问题或完成单个 GIS 操作 | 从规划目标到空间方案和成果交付的完整闭环 |
| 调度方式 | 固定流程或自由调用工具 | LLM 提议 + Policy 审批 + typed command |
| 规划决策 | 模型生成建议 | 证据、规则、约束和 Solver 共同形成决定 |
| 错误处理 | 重新提问或整体重试 | 定位责任阶段，定向修复、重算、回滚或人工确认 |
| 可解释性 | 结果说明或普通引用 | Artifact、关系、版本、父链、事件和空间 diff 全程追踪 |
| 输出形态 | 文本、局部分析结果或单张图 | 规划对象、地块变化、地图、图层、平衡表和交付包 |

### 对比结论

本项目的差异不在于“使用了某一个更大的模型”，而在于把语言智能、空间智能、证据治理和规划
执行组织成一个完整系统。

---

## 第 8 页：目标价值与建设路线

### 目标价值

- 提高村庄规划资料整理、空间分析和方案生成效率；
- 将分散的文本、图件、GIS 和知识库统一到可审计流程；
- 降低 LLM 幻觉、地点错位和空间结果不可解释风险；
- 支持规划人员进行人工复核、方案比较和持续迭代；
- 让规划成果从“生成一张图”升级为“形成一套可追溯交付物”。

### 目标建设路线

```text
接口与状态冻结
  → 数据 / Artifact 基础设施
  → L1/L2/L3 与规划程序组装
  → KG / 地点证据 / EXPLORE / 外部搜索
  → 空间候选 / Solver / Worker 执行
  → 自动修复 / 多模态证据
  → 统一交付与验收
```

### 结束语

> 让 LLM 参与规划，但让证据、空间计算和审计机制决定规划能否成立。
