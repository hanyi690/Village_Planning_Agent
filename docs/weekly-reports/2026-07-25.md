# 周报（2026-07-21 ~ 2026-07-25）—— 面向评审

## 本周核心成果

### 1. KG 四层架构 + 增量设计（v4.4）

知识图谱从单层结构重构为**四层语义架构**：

| 层次 | 内容 | 规模 |
|------|------|------|
| L1 现状层 | 660 个地块、175 条道路、44 个设施等现状实体及拓扑关系 | 1,549 个 `touches` 关系 |
| L2 约束层 | 耕地保护、生态保护、历史保护等 3 条管控规则 | 含三区三线 |
| L3 意图层 | 路网连通性推理（同一道路穿越的地块对） | 207 个 `connected_via_road` |
| L4 规划变更层 | **PlanBlock 增量设计**——只存变更 delta，而非全量镜像 | 3 个变更示例（37 triples，vs 原方案约 6,600 triples） |

**关键设计思路**：原有方案 `PlannedState` 为每轮规划生成一套完整镜像，数据膨胀 31%。改用 `PlanBlock` 增量模式后，变更只占 0.17%，且支持 `split`（地块拆分）、`merge`（合并）、`reclassify`（重分类）三种基本操作，通过 `derived_from` 链接追溯变更来源。

**验证**：金田村实际数据构建 21,253 个三元组，73 项自动化测试全部通过，包括 SPARQL 查询验证、路网连通查询、L1→L4 有效用途回退。

### 2. Pipeline 全链路跑通 + 性能优化

金田村完整管线（加载数据 → 构建 KG → MIP 分配 → 生成图层 → 渲染出图）在 7-23 和 7-24 两次实际运行中验证通过：

| 指标 | 7-23 首次 | 7-24 优化后 | 提升 |
|------|-----------|-------------|------|
| 总耗时 | 63 秒 | 35.6 秒 | -43% |
| MIP 分配 | 5.4 秒 | 2.7 秒 | -50% |
| KG 构建 | 8.2 秒 | 6.1 秒 | -26% |
| 渲染出图 | 11.1 秒 | 2.9 秒 | -74% |
| 约束数 | 1 条 | 4 条 | +300% |
| 验证检查 | 8 项 | 9 项（含 VNE 合规） | +1 |

产出 11 个 GeoJSON 图层和 3 张渲染图（规划分区图、对比图、合成图），设施点从注记图层中独立拆分。

### 3. Schema 层抽象（v4.0-v4.3）

数据模型从"以图层语义为中心"重构为**"以数据结构为中心"**，核心变化：
- **几何类型化**：`SpatialFeature` → `PointFeature` / `LineFeature` / `PolygonFeature`，构造时强制校验几何类型
- **现状/规划分离**：地块拆为 `current_landuse` 和 `planned_landuse` 两个独立字段
- **项目级视图**：`GISDataBundle` → `ProjectDataView`（多村）+ `VillageBundle`（单村）
- **规范补全**：对照 GB50445、GB/T 21010、QMDLTB 等 21 份规范，补充了 10 个缺失字段、6 类设施子类型

### 4. Data 层双轨设计

- **已注册类型**：走严格校验（28 个 layer_type 映射）
- **未注册类型**：自动推断（几何类型分桶 → 字段名知识库匹配 → 编码值字典查表 → 动态模型生成）
- 栅格和表格各有一套独立推断流程
- 配置拆分：`sources.yaml`（物理连接）+ `projects.yaml`（项目逻辑）
