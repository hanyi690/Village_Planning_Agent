# Complete Planning Layers Execution Plan

## Goal

Make a fresh planning run produce a complete, reasonable, source-backed set of
planning layers. Every L3 planning claim must have an auditable disposition;
spatial intents that are not yet located must continue to GROUND as pending
requirements instead of disappearing during admission. GROUND, candidate
production, mixed SELECT, EXECUTE, VALIDATE, RECONCILE, and DELIVER must remain
strict about geometry and certificates while allowing LLM drafts to be
semantically incomplete and recoverable.

## Global Constraints

- Preserve unrelated dirty-worktree changes. Do not reset, checkout, or
  overwrite existing user edits.
- Do not restore CurrentAsset, DemandRegisterRow, CoverageDecision, or any
  other retired parallel register/compatibility path.
- L3 may produce typed semantic intent and grounding requirements, but never
  coordinates, WKT, GeoJSON, BSM identities, final candidates, or solver
  certificates.
- Missing locator/evidence on a future spatial intent is a pending grounding
  requirement, not a silent omission. Existing-fact assertions still require
  exact source identity before they are treated as facts.
- Formal EXECUTE and delivery require approved, source-backed, validated
  geometry and a feasible ScenarioSet. Diagnostic artifacts must not be
  promoted to formal planned layers.
- Deterministic checks own IDs, units, CRS, geometry, topology, area/capacity,
  lineage, and solver certificates. LLMs own semantic interpretation,
  relation proposals, missing-prerequisite explanations, and alternatives.
- Each task must add or update focused tests and leave a recorded checkpoint.

## Tasks

### Task 1: Preserve pending spatial intent during L3 admission

Change the L3 program boundary so a typed `spatial_intervention` claim with
valid semantic parameters but missing locator/evidence is represented as a
pending grounding item. Keep the strict intervention contract for items that
are actually executable, and retain one disposition for every claim.

### Task 2: Compile pending intent into GROUND requirements

Compile pending items into typed spatial query/evidence requirements and
task-level prerequisites. GROUND must be able to resolve place hints,
candidate geometry, demand points, parcel membership, network snapshots, and
topology without requiring L3 to fabricate them.

### Task 3: Connect candidate producers and mixed solver subproblems

Route facility, road, zone, site, protection, and restoration intents to the
appropriate candidate producers. Compose parcel, coverage, network, and
topology subproblems into one authoritative ScenarioSet instead of selecting
one global solver kind for the whole village.

### Task 4: Complete materialization and delivery coverage

Preserve strict approval/atomic execution and make delivery account for every
mandatory planning family. A target is either materialized, approved as not
applicable, or explicitly deferred with evidence; it cannot disappear.

### Task 5: Fresh end-to-end and frontend verification

Create a new session from the current inputs, verify same-run CAS lineage,
feasible ScenarioSet, approval, execution, validation, reconciliation,
delivery, non-empty planned layer collections, and frontend visibility.
